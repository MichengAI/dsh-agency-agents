# 安装、构建与发布

## 安装

使用 `dsh plugin --profile <profile> add <插件目录或包名>` 安装；bundle patch 会挂载 `agency-agents`。安装后使用 `dsh --profile <profile> --dump-config` 确认组合结果。

## 验证

- `pnpm build`：先做 TypeScript 类型检查，再构建 ESM 和声明文件。
- `pnpm test`：验证 frontmatter、递归扫描、外部 root 错误和包内默认资产。
- `pnpm verify`：验证发布清单、DSH bundle、构建入口和许可证资产。
- 真实运行：使用隔离 profile 召唤一个智能体，确认 provider、persona 和工具过滤均生效。

## 发布

`prepublishOnly` 会依次运行构建、测试和发布验证。发布前检查根目录 Apache `LICENSE`、`NOTICE` 和 `assets\agency-agents\LICENSE` 都在包内。

本包发布到官方 npm registry，包名为 `@michengai/dsh-agency-agents`。`publishConfig` 已固定官方 registry 和 `public` access，避免本机下载镜像影响发布目标。

默认发布路径是 GitHub Actions 的 npm 受信发布（OIDC）：推送与 `package.json` 版本一致的 `v*` 标签后，工作流会安装锁定依赖、执行 `pnpm prepublishOnly`，最后运行 `npm publish`。工作流不保存 `NPM_TOKEN`，也不注入令牌式 registry 配置。

首次启用前，维护者需在 npm 包设置的“Trusted Publisher”中绑定 GitHub Actions：用户 `MichengAI`、仓库 `dsh-agency-agents`、工作流文件 `publish.yml`，并仅允许 `npm publish`。绑定完成后可按以下方式发布：

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
npm version patch
git push origin main --follow-tags
```

`npm version` 会同步创建与包版本匹配的标签；工作流会拒绝标签和 `package.json` 版本不一致的发布。需要紧急人工回退时，先使用 `npm whoami --registry=https://registry.npmjs.org/` 确认登录账号，再执行 `npm publish`。
